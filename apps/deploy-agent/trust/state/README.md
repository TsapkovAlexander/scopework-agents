# Корни подписи желаемого состояния

Открытые ключи офлайн-корней, которыми агент развёртывания проверяет подпись
желаемого состояния ([ADR-0082](../../../../docs/adr/ADR-0082-offline-signing-key-for-agent-trust.md),
решение владельца 23.09.2026). Корень подписывает только сертификат рабочего
ключа машины-подписанта; манифест подписывает рабочий ключ, и агент принимает
его, если сертификат заверен одним из этих корней и не истёк.

## Формат

Как у ключей выпуска ([../release/README.md](../release/README.md)): один
корень — один файл `<идентификатор>.pub`, одна строка std-base64 сырых 32 байт
открытого ключа Ed25519; имя без `.pub` — идентификатор корня.

## Закрытых ключей здесь не бывает никогда

Закрытый ключ корня лежит офлайн у владельца. Рабочий ключ подписанта сюда не
кладётся тоже: он живёт на подписанте и меняется со сроком своего сертификата,
а вшитый в бинарь ключ меняется только новой версией агента. Любой файл,
похожий на закрытый ключ, в этом каталоге роняет `npm run test:agent-release`.

## Кто кладёт

Человек, после церемонии выпуска корня по ADR-0082.

## Как корень попадает в агента и что это стоит

Сборка вшивает корни флагом
`-ldflags "-X tracedocs.ru/deploy-agent/internal/agent.trustedStateRootsRaw=<b64,b64>"`
и передаёт его, только когда здесь есть ключи. Символ объявляет код проверки
подписи состояния (`internal/agent/state_trust.go`, штаб Г). Компоновщик Go молча
пропускает `-X` для несуществующего символа, поэтому
`npm run test:agent-release` падает, если корни здесь есть, а символа в агенте
нет: иначе бинарь собрался бы без корней и об этом не сказал бы никто.

Новый или снятый корень меняет бинарь, значит — подъём версии агента и новый
выпуск. Смена корня — двумя корнями сразу (ADR-0082, п. 4): новый добавляется
одной версией, старый снимается следующей.
