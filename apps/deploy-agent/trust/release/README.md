# Ключи подписи выпуска агента

Открытые ключи, которыми агент развёртывания проверяет подпись нового бинаря
при самообновлении ([ADR-0082](../../../../docs/adr/ADR-0082-offline-signing-key-for-agent-trust.md),
задача С1.3). Ключ вшит в бинарь, а не приходит с платформы: иначе проверка
свелась бы к «платформа сказала, что это она».

## Формат

- Один ключ — один файл `<идентификатор>.pub`. Имя без `.pub` — идентификатор
  ключа: по нему ключ называют при церемонии, в отпечатках `version --trust` и
  при снятии.
- Содержимое — одна строка: std-base64 (с `=` на конце) сырых 32 байт
  открытого ключа Ed25519. Ровно то, что печатает
  `node scripts/deploy/sign-agent-release.mjs keygen <путь>` после строки
  «Публичный ключ для сборки агента:». Без PEM и заголовков.

## Закрытых ключей здесь не бывает никогда

Закрытый ключ лежит офлайн у владельца и не попадает ни в репозиторий, ни на
сервер, ни в CI. Ключ, доступный сборке, не защищает от взлома сборки — а
именно от этого подпись и заведена. Любой файл, похожий на закрытый ключ, в
этом каталоге роняет `npm run test:agent-release`.

## Кто кладёт

Человек, после церемонии выпуска ключа по ADR-0082: пара заводится на
офлайн-машине, сюда ложится только `.pub`, отпечаток публикуется для
сверки клиентом.

## Как ключ попадает в агента и что это стоит

Сборка склеивает все `*.pub` через запятую и вшивает их флагом
`-ldflags "-X tracedocs.ru/deploy-agent/internal/agent.trustedKeysRaw=<b64,b64>"`.
Каталог без ключей — агент подпись не проверяет и говорит об этом в докладе.

Новый или снятый ключ меняет бинарь, значит — подъём версии агента
(`apps/deploy-agent/VERSION`, запись в `CHANGELOG.md`) и новый выпуск. Смена
ключа — двумя ключами сразу (ADR-0082, п. 4): новый добавляется одной версией,
старый снимается следующей. Иначе агенты, не успевшие обновиться, отвергли бы
выпуск, подписанный новым ключом, и ставились бы заново руками.
