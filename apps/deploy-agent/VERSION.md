# Версия агента развёртывания

Номер лежит в файле `VERSION` рядом с этим текстом, читается сборкой выпуска
(`scripts/build-deploy-agent.sh` — единственная сборка агента, в образ
платформы он не собирается) и генератором константы для платформы
(`scripts/sync-agent-versions.mjs`). Формат — `MAJOR.MINOR.PATCH`. Сборка,
подпись и выкладка выпуска — `docs/runbooks/agent-release.md`.

**Других источников номера нет.** Выкат и CI версию в сборку не передают: до
23.09.2026 они подставляли хеш коммита, агент докладывал его вместо номера и
отклонял каждое обновление — сравнить хеш с номером нельзя, а откат агент не
принимает.

**Нумерация своя, от версии платформы независимая.** Платформа выкатывается по
нескольку раз в день, агент меняется редко; общий номер означал бы, что клиенту
каждый день предлагают обновить программу на его сервере, в которой ничего не
изменилось.

## Что значит каждый разряд

| Разряд | Когда растёт |
|---|---|
| `MAJOR` | агент перестаёт работать со старой платформой или меняет поведение на сервере клиента: новые права, другой набор запускаемых команд, иной формат состояния на диске |
| `MINOR` | агент научился чему-то новому, старое работает как работало |
| `PATCH` | починка: то же поведение, но без ошибки |

Разряд выбирается по тому, что увидит **клиент на своём сервере**, а не по
объёму работы. Сомневаетесь между MAJOR и MINOR — берите MAJOR: цена ошибки
несимметрична. Крупное обновление ждёт нажатия владельца, мелкое приезжает
само, и клиент, у которого поведение сервера изменилось без спроса, второй раз
агента не поставит.

## Порядок подъёма

Версия поднимается тем же изменением, что и код агента:

1. новый номер в `VERSION`;
2. запись в `CHANGELOG.md` рядом;
3. `node scripts/sync-agent-versions.mjs` — константа для платформы;
4. `npm run deploy-agent:lock` — замок `VERSION.lock`.

Держит `npm run test:agent-versions`: версия без записи и запись без версии
одинаково роняют прогон, а замок хранит хеш исходников бинаря (`*.go` без
тестов, `go.mod`, `go.sum`, открытые ключи `trust/**/*.pub`) и краснеет, если
код изменился, а версия нет. Ключ входит в хеш, потому что сборка вшивает его
в бинарь: новый или снятый ключ — это новый бинарь и, значит, новая версия.
Команда замка отказывает, пока номер не поднят, — освежить замок вместо
подъёма нельзя. `install.sh` в хеш не входит: в бинарь он не попадает, и
правка установщика подъёма версии не требует.
